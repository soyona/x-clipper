# X Article Clipper 产品设计规范

本文件是 X Article Clipper（技术项目名 `x-clipper`）产品定义、用户旅程、场景、信息架构、产品状态和 UI 设计的单一权威来源。X DOM owner、锚点和注入生命周期以 `docs/development/x-dom-integration.md` 为准；schema、消息和持久化原子性以 `docs/development/repository-contracts.md` 为准。

## 产品定义

- 定位：X Article Clipper 将海量 X 信息与用户有限的注意力匹配，优化的是信息吸收效率，而不是采集速度。
- 核心任务：用户在碎片时间发现有价值的 Post 或 Article 时，一次操作保存完整快照；后续在合适时间精读，或转为创作素材。
- 管理对象：Post、Article 和作者。Post 与 Article 共用同一内容生命周期；阅读状态与素材状态相互独立。
- 完整性：保存当前作者写的当前 Post 或 Article 正文及图片；不保存引用 Post、回复、评论、线程、视频或音频文件。视频只显示“含视频，仅原文可播放”。
- 质量边界：价值由用户判断；不引入 AI 评分、摘要、推荐或内容生成。
- 成功标准：用户能够完成 `发现 → 加入待读 → 本地精读 → 保存为素材 → 使用完成`，即使 X 原文删除、修改或不可访问，已保存快照仍可阅读。

### 非目标

- 不采集引用 Post、回复、评论、线程上下文、视频或音频二进制内容。
- 不做自动推荐、AI 辅助、发布系统、云同步、X API 抓取或开发者后台上传。
- 不把统计、设置、发布链接或导航未读角标恢复为一级产品能力。

## 完整用户旅程

主闭环：`发现 Post/Article → 加入待读 → 本地精读 → 保存为素材 → 标记已使用`。

| 阶段 | 用户动作 | 系统结果 |
|---|---|---|
| 发现 | 在 Post 或 Article 详情主内容菜单选择“加入待读” | 立即采集当前内容完整文本与图片并本地持久化；Toast 确认 |
| 回看 | 打开 Side Panel“待读”，按未读/已读/全部筛选 | Post 四行摘要、Article 现有 Card 样式；点击进入本地阅读器 |
| 精读 | 在本地阅读器阅读完整正文与图片 | 首次打开记录阅读时间并标记已读；原文链接仅作补充 |
| 转素材 | 在本地阅读器选择“保存为素材” | 同一内容增加素材状态，不复制快照、不离开阅读集合 |
| 复用 | 在素材库加标签并标记已使用 | 只更新素材与标签状态，原始快照保持不变 |

失败规则：正文不存在时不创建记录；图片保存失败时保留文本并标记快照不完整；重复加入只恢复为未读，不覆盖第一次保存的内容。唯一补全例外是已有 Post 正文为当前更长正文的完整前缀，此时允许原子补全正文与图片；非前缀变化视为原文修改，不覆盖本地快照。

## 场景、入口与动作矩阵

| 场景 | 是否注入 | 主要动作 | 完成结果 |
|---|---|---|---|
| 普通 Post 列表 | 否 | 无；点击 Post 进入详情页后操作 | 避免把列表折叠正文误存为完整快照 |
| Post 详情 | 仅当前 URL 对应的主 Post | 加入待读/从待读移除、复制 Markdown | 保存完整正文与当前 Post 图片 |
| Article 列表 | 否 | 无；点击 Article 进入详情页后操作 | 避免列表上下文产生不完整快照 |
| Article 详情 | 仅当前权威主 Article | 加入待读、素材、预览/复制、作者 | 更新同一内容与作者状态 |
| Side Panel 待读 | 始终可用 | 搜索、未读/已读/全部、本地阅读、打开原文 | 管理阅读状态 |
| Side Panel 素材库 | 始终可用 | 搜索、筛选、标签、本地阅读、使用状态 | 管理创作素材状态 |
| Side Panel 作者 | 始终可用 | 打开作者 Articles、取消收藏 | 继续发现或移除作者 |

## Side Panel 信息架构

Side Panel 保留“待读 / 素材库 / 作者”三个一级页面。待读默认显示未读，复用现有筛选控件提供“未读 / 已读 / 全部”。Post 复用 Article 外层作者 Card，正文直接显示四行；有图时显示首图与图片总数；Article 保持既有内层 Article Card。点击两者均打开本地阅读器。手动“导出备份 / 恢复备份”位于作者页底部的低优先级“数据管理”区域，不新增一级导航；恢复采用合并策略，不覆盖设备上已有记录。

## 核心产品状态

每个 `ContentItem` 只有一份首次快照，同时拥有两条独立状态轴：`readState = unread | read`；`materialState = none | unused | used`。再次加入待读把已有内容恢复为 `unread`，不覆盖快照；仅当已有 Post 正文是新采集正文的严格前缀时执行缺失尾部补全，并保留素材状态、标签和生命周期时间。保存为素材只把 `materialState` 设为 `unused`。作者按 handle 独立去重。

## 视觉语言

- 使用 `TwitterChirp, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` 字体栈和当前 X light token：主文字 `#0f1419`、次级文字 `#536471`、品牌蓝 `#1d9bf0`、分隔线 `#eff3f4`、浅背景 `#f7f9f9`。
- 使用 1px 分隔线、圆形或胶囊控件、紧凑信息密度以及 X 式 hover、focus、active、disabled、destructive 状态。
- 不引入 SaaS 卡片、Windows 弹窗、自创颜色、装饰性渐变或无语义圆角。内容分组优先依靠层级、间距和分隔线。
- 保持当前 light token 体系；主题系统不在当前产品范围内。

## 图标契约

- 图标先满足动作语义，再满足 X 风格。统一使用 `24×24` viewBox、24px 菜单槽位、18.75–26px 可见尺寸、`currentColor`、固定点击热区和当前页填充态。
- X Article Clipper 页面入口使用独立的圆形书写轨迹与铅笔图形；待读使用收件托盘；素材库使用 Bookmark；作者使用人物集合。
- X 页面菜单的状态动作遵循 X 官方语义：待读和素材的加入／保存使用对象轮廓态，移出使用同一对象的实心态；作者保留 X 的 person-add/person-remove 图形。三种反向动作均仅将图标设为 `#f4212e`，标签保持中性色。素材使用用户提供的 X 官方 Bookmark／Remove from Bookmarks path；预览 Article 使用 Article-eye；复制 Markdown 使用 Markdown-copy。
- UI 图标的项目级单一权威源为 `assets/icons/x-clipper-ui-icons.svg`，稳定 `symbol id`、语义映射、状态和验收图以 `docs/design/icon-system.md` 为准。运行时即使因 Content Script 隔离而采用内联 SVG，也必须与权威源保持相同图形和 token。
- 新增界面必须先复用权威图标库；缺少语义时，必须先取得用户提供的 X SVG／组件证据，再同步补充图标库、规范图、语义映射和契约测试。不得在业务代码中先加入临时 path，后补规范。
- 不复制已连接的 X DOM/SVG，不用 emoji、Unicode 符号或临时字符替代图标。缺少图标证据时向用户索取 DevTools 中的最小 SVG 片段，不自行猜测 path。
- 品牌 Logo 使用用户确认的方向 3：圆形书写轨迹、正文短线与正在书写的铅笔。矢量源为 `assets/icons/x-clipper-icon-source.svg`，页面内单色入口源为 `assets/icons/x-clipper-entry.svg`；两者共享确定性 `24×24` 几何。品牌只使用纯黑与纯白，不得包含或近似描摹 X/Twitter 官方 Logo 与商标 path。
- 素材菜单的打开原文、编辑标签、使用状态和删除图标，以及素材预览动作图标，来源于用户确认的方案 1 设计图；保持 `24×24`、约 `1.9px` 圆角描边、固定图标槽和 `currentColor`。删除图标只在 destructive 动作中使用危险色。
- 完整语义映射、导航状态和设计证据以 `docs/design/icon-system.md` 为权威规范；后续按钮必须先按动作语义选择该规范中的图标，不得仅因图形相似复用相反动作的图标。
- 作者认证徽标复用用户从 X DevTools 提供的原始 `22×22` SVG：蓝色认证使用 `#1d9bf0` 单色 path，金色组织认证保留原始双渐变。待读、素材库和作者页共享同一徽标组件、尺寸与类型数据；作者 handle 的次级色不得覆盖徽标颜色。

## 组件规则

### X 页面入口与菜单

- 入口拥有独立 DOM、状态和菜单生命周期；视觉结构可参考已取证的 X slot，但不得复用 X React 状态或 Portal。
- 菜单行高 44px，图标槽 24px，图文间距 12px。文本左对齐，动态文案不得改变图标槽和文字起点。
- 再次点击入口切换菜单；点击外部、`Escape`、滚动或缩放关闭。关闭后清理 `aria-expanded`；键盘触发与鼠标触发执行同一动作。
- destructive 动作使用 X 的危险语义颜色；disabled 不接受点击；focus-visible 必须清晰且不改变布局。

### Side Panel 导航与内容

- 一级导航使用固定图标热区；active 使用 `#1d9bf0` 填充图标且无持续背景／边框，hover 使用 X 中性圆形背景，focus-visible 单独使用 2px 蓝色焦点环。状态切换不移动内容。
- 待读提供本地阅读、打开原文和阅读状态切换；素材库提供搜索、标签、本地阅读、复制和使用状态；作者只提供打开作者 Articles 与取消收藏。
- 空状态一句话说明当前为空以及唯一下一步，不增加营销文案或装饰插画。
- 对话框只用于不可逆确认，使用扩展自身 DOM；`Escape` 关闭，取消为默认安全动作，确认删除使用 destructive 状态。

### Preview 与 Toast

- 本地阅读器显示完整已保存快照、复制 Markdown 和打开原文；尚未进入素材库时显示“保存为素材”。视频只提供原文播放提示。
- Article 使用标题与正文层级；Post 不生成 Article 标题区，已保存正文只按原始段落结构渲染一次，不得把同一正文同时作为大标题和正文重复显示。
- 首次加入待读或保存素材需要固化图片时，菜单动作行立即切换为“正在加入待读…”或“正在保存素材…”并暂时禁用菜单动作；最终 Toast 只在本地提交完成后出现。
- Toast 只确认刚完成的结果或说明可操作错误；不重复页面标题，不长期占据内容区域。

## 文案原则

- 使用用户目标而不是内部实现名：待读、素材、作者、复制 Markdown、保存为素材、标记已使用。
- 不向用户暴露 candidate、materialize、job、schema、capture 等工程状态。
- 菜单动词与结果一致；互斥状态使用“加入/移除”“收藏/取消收藏”“标记为已使用/未使用”。

## 证据与验收边界

- 禁止自动启动 Chrome、浏览器自动化或真实 X 视觉验收。
- 当现有文档和源码不足以确认 X DOM、SVG、尺寸或交互状态时，停止实现相关未知部分，并明确列出需要用户从 Chrome DevTools 提供的最小节点源码、属性或计算样式；禁止依据页面印象猜测。
- 静态测试、语法检查和源码审查只能证明项目契约，不得表述为真实 X DOM、剪贴板权限、视觉对齐或扩展加载行为已通过。
